| **إجمالي الأصناف المسجلة** | **548 صنفاً** | `=COUNTA(productsrep55!B2:B1000)` عبر جميع مراحل السلسلة بدون أي فاقد |
| **إجمالي وحدات المخزون الفعلي** | **2,608 قطعة** | `=SUM(productsrep55!F2:F1000)` مجموع الأرصدة المتاحة بالمعرض والمخزن |

### ب. مسار تدفق البيانات عبر المراحل الـ 6 (Data Pipeline Architecture)

1. **المرحلة الأولى — جرد المحل الخام والتطبيع المالي ([productsrep55](https://docs.google.com/spreadsheets/d/1t3peJz8vDzCDUVqCBHOZuam9Ef91sKjBD8v9XIZVFQ0/edit))**:
   * تُصدر منظومة الكاشير/الجرد بالمحل كشف المواد في ورقة `productsrep` مرتباً من اليمين إلى اليسار (العمود `L` رقم المادة، `K` اسم المادة، `J` الكمية، `I` الوحدة، `H` سعر الجملة/الشراء، `F` سعر البيع قسط، `D` التصنيف، `B` سعر الكاش)، مع وجود دالة `=NOW()` في الخلية `R2`.
   * تقوم ورقة `productsrep55` بعكس وتطبيع هذا الجدول في الخلية `A1` عبر المعادلة `=VSTACK({"كود الصنف",...}, CHOOSECOLS(productsrep!A7:L1000, 12, 11, 9, 4, 8, 10))`، وتحسب القيمة الإجمالية (`G1`)، وسعر القسط (`H1`)، والربح (`I1`)، ونسبة الربح (`J1`)، وتسحب سعر الكاش في `K1` (`=productsrep!B6:B1000`)، وتنقل طابع التحديث الزمني إلى `N1` (`=productsrep!P2:S3`).
2. **المرحلة الثانية — محرك التسعير والمحاسبة ([DBPRICE](https://docs.google.com/spreadsheets/d/1PSIO5mViH_kj_BxCUI8kH-0zofEKbLU07W-ZtFANTE8/edit))**:
   * تستورد ورقة `impdata` كامل جدول `productsrep55!A:P` عبر `IMPORTRANGE`.
   * تحسب ورقة `التسعير` الأسعار التلقائية المقترحة (`سعر الكاش AUTO` بهامش 45% للأصناف تحت 100 ج.م و25% لما فوقها، و`قسط 10 شهور` و`قسط يومي`) وتحتفظ بأسعار البيع الفعلية (الكاش في `I` والقسط في `H` والتصنيف في `M`).
   * تجمع ورقة `DBPRICE` جدول التصدير النهائي الموحد من `التسعير!A2:H1000` (عبر مرجع داخلي مباشر في `A1`)، وتربط الكمية في `I1` بدالة `XLOOKUP` على كود الصنف من `impdata!A:A`، وتمرر سعر الكاش في `J1` والتصنيف في `K1` وطابع التحديث الزمني في `L1` (`=impdata!N1`).
3. **المرحلة الثالثة — الإثراء التسويقي وشاشات نقاط البيع ([priceimg](https://docs.google.com/spreadsheets/d/1xWqo7qvuL7b8iLwDTG7hzjnTSRULjz_l0JFJ56CdSyI/edit))**:
   * تسحب ورقة `DATAIMP` الأعمدة المالية والمخزنية الحية من `DBPRICE!A:M` (الكود، الاسم، الكاش، القسط، الكمية، التوقيت، والتصنيف)، وتحسب عمود `التوافر` (`F1`) تلقائياً (`متوفر` إذا كانت الكمية `> 0` وإلا `غير متوفر`).
   * تدمج ورقة `DATAIMP` حقول الإثراء التسويقي (`رابط الصورة` في `H1`، `الوصف` في `J1`، `العلامة التجارية` في `L1`) من ورقة `priceimg` عبر مطابقة كود الصنف بدالة `XLOOKUP(TO_TEXT(c), ...)`.
   * تتغذى أوراق نقاط البيع الفرعية (`سعر الكاش`، `سعر القسط`، `المخزون`، `بالباركود`) من هذا المصنف لخدمة الكاشير وموظفي المعرض.
4. **المرحلة الرابعة — قاعدة بيانات الكتالوج النهائية ([pric](https://docs.google.com/spreadsheets/d/1ev1AhcQmnhwYQuU5QV2drdGdiUW6zY6eXz4QabmFOMc/edit))**:
   * تستورد ورقة `0` في الخلية `A1` كامل نطاق `DATAIMP!A1:O1000` من ملف `priceimg`، وتصفي الصفوف الفارغة، وترتب جميع الـ 548 صنفاً تنازلياً حسب الكمية (`SORT(rows, 5, FALSE)`) مع الحفاظ التام على الأكواد النصية والرقمية.
   * تعيد ورقة `Menu` ترتيب الأعمدة في الـ 11 عموداً القياسية التي يقرأها السيرفر (`A:F` البيانات الأساسية، `G` رابط الصورة، `H` التصنيف، `I` الوصف، `J` العلامة التجارية، `K1` طابع التحديث الزمني).
5. **المرحلة الخامسة — الخادم السحابي والكاش المجزأ (`Code.gs` v5.1.0)**:
   * يقرأ `Code.gs` ورقة `Menu` ويعقم البيانات ضد حقن الصيغ (`Formula Injection`)، ويخزن النتيجة في `CacheService` مقسمة إلى قطع آمنة بترميز UTF-8 (حتى 50 قطعة × 80KB) لمدة 10 دقائق، ويقدم واجهة REST API تدعم الترقيم (`offset` و`limit`) ومحمية بـ `Rate Limiting` (120 قراءة/دقيقة و30 كتابة/دقيقة) و`LockService` و`ADMIN_SECRET`.
6. **المرحلة السادسة — واجهة المتجر (`index.html`) ولوحة الإدارة (`admin.html`)**:
   * تعرض `index.html` المنتجات للعميل بسرعات فائقة عبر استراتيجية `Stale-While-Revalidate` فوق قاعدة بيانات المتصفح `IndexedDB` (الإصدار 4)، وتوفر البحث الفوري، الفلترة بالتصنيف والماركة والسعر والكمية، وحاسبة خطط التقسيط التفاعلية، وإرسال الطلبات عبر واتساب.
   * توفر `admin.html` للمشرفين تعديل الأسعار والكميات وحالة التوفر، وإضافة أصناف جديدة أو حذفها ناعماً (`Soft Delete`) عبر طلبات `POST` آمنة وموثقة.

## 🛡️ 5. الحل الجذري والنهائي لمشكلة انزلاق الصفوف (Row Misalignment) في جداول البيانات

### أ. تشخيص الأسباب الثلاثة لانزلاق الصفوف واختفاء البيانات

كشف الفحص الهندسي الدقيق لملفات الشيت الأربعة عن **3 أسباب تقنية** تؤدي لانزلاق الصفوف أو مسح أعمدة الإثراء التسويقي:

1. **السبب الأول — الانزلاق بين الأعمدة الديناميكية والثابتة (`Dynamic-Static Row Misalignment`)**:
   * عندما تستورد ورقة `DATAIMP` الأعمدة المالية والمخزنية (`A:E` و`G` و`K`) ديناميكياً عبر `IMPORTRANGE` من `DBPRICE`، بينما تُكتب أعمدة الإثراء (`H` رابط الصورة، `I` اسم مختصر، `J` الوصف، `L` العلامة التجارية) كقيم يدوية ثابتة في نفس الورقة دون ربطها بـ `كود الصنف`، فإن أي إضافة أو حذف أو إعادة ترتيب لصف في `productsrep55` أو `DBPRICE` يحرك الأعمدة المستوردة لأعلى أو لأسفل بينما تبقى الصور والأوصاف الثابتة في أرقام صفوفها القديمة، فيأخذ كل منتج صورة ووصف منتج آخر.
2. **السبب الثاني — كارثة المسح الدائري في سكريبت `copyDataimpToPrice()` (`Circular Wipe Race Condition`)**:
   * في مصنف `priceimg` (الموثق في `priceimg!README!J2`)، كانت الدالة القديمة `copyDataimpToPrice()` تنفذ الكود التالي بالترتيب:
     ```javascript
     targetSheet.clear(); // 1. يمسح ورقة priceimg بالكامل أولاً!
     const sourceRange = sourceSheet.getDataRange();
     const values = sourceRange.getValues(); // 2. يقرأ DATAIMP بعد مسح priceimg!
     targetSheet.setValues(values);
     ```
   * **ماذا يحدث عند تشغيل هذا السكريبت مع وجود معادلات `XLOOKUP` في `DATAIMP` تقرأ من `priceimg`؟**
     فور تنفيذ `targetSheet.clear()` تُمسح ورقة `priceimg`، فتعيد معادلات `XLOOKUP` في `DATAIMP!H1, J1, L1` حساب نفسها فوراً وتُرجع قيماً فارغة `""` لأن المصدر `priceimg` أصبح فارغاً! ثم يقوم السطر التالي `sourceRange.getValues()` بقراءة تلك القيم الفارغة من `DATAIMP` وكتابتها داخل `priceimg`، فيؤدي ذلك إلى تصفير جميع الأوصاف والصور والماركات!
3. **السبب الثالث — انزلاق مراجع الأعمدة في `DBPRICE!dataorg` (`Column Lookup Misalignment`)**:
   * في مصنف `DBPRICE` داخل ورقة `dataorg`، تبحث الخلية `D1` (`تاريخ اخر شراء`) في العمود `'مخزون المحل الوارد'!F:F` (وهو في الحقيقة عمود `الكمية الموجودة`)، وتبحث الخلية `E1` (`الكمية المشتراه`) في العمود `'مخزون المحل الوارد'!D:D` (وهو عمود نصي يحتوي على `التصنيف` مثل `"موازين"`)، مما يؤدي لظهور خطأ `#VALUE!` في كامل العمود `G` (`القيمة الإجمالية للشراء = E * F`)!

### ب. الحل الهندسي المتكامل والدائم لمنع انزلاق الصفوف 100%

#### الخطوة 1: تثبيت ورقة `priceimg` كخزنة مرجعية مفهرسة بـ `كود الصنف` وربط `DATAIMP` بها عبر `XLOOKUP`

تُحفظ البيانات التسويقية الثابتة (`رابط الصورة` في `H`، `اسم مختصر` في `I`، `الوصف` في `J`، `العلامة التجارية` في `L`) داخل ورقة `priceimg` مرتبطة بـ `كود الصنف` في العمود `A`. وفي ورقة `DATAIMP` (مع بقاء الصفوف `2:1552` في الأعمدة `H, J, L` فارغة من أي نص يدوي)، توضع معادلات الربط المفتاحي التالية في الصف الأول:

* **في الخلية `DATAIMP!H1` (رابط الصورة)**:
```excel
={"رابط الصورة"; MAP(A2:A1000, LAMBDA(c, IF(c="", "", IFERROR(XLOOKUP(TO_TEXT(c), INDEX(TO_TEXT(priceimg!A:A)), priceimg!H:H, ""), ""))))}
```

* **في الخلية `DATAIMP!J1` (الوصف)**:
```excel
={"الوصف"; MAP(A2:A1000, LAMBDA(c, IF(c="", "", IFERROR(XLOOKUP(TO_TEXT(c), INDEX(TO_TEXT(priceimg!A:A)), priceimg!J:J, ""), ""))))}
```

* **في الخلية `DATAIMP!L1` (العلامة التجارية)**:
```excel
={"العلامة التجارية"; MAP(A2:A1000, LAMBDA(c, IF(c="", "", IFERROR(XLOOKUP(TO_TEXT(c), INDEX(TO_TEXT(priceimg!A:A)), priceimg!L:L, ""), ""))))}
```

> **لماذا يمنع هذا النمط انزلاق الصفوف نهائياً؟** لأن كل منتج في `DATAIMP` يبحث عن صورته ووصفه وماركته باستخدام `TO_TEXT(c)` (كود الباركود الفريد للصنف) وليس برقم الصف، فمهما تغير ترتيب الأصناف أو أُضيف صنف في المنتصف أو حُذف صنف، تنتقل الصورة والوصف والماركة مع كود الصنف الخاص بها تلقائياً.

#### الخطوة 2: استبدال سكريبت `copyDataimpToPrice()` بالدالة الآمنة `copyDataimpToPriceSafe()`

لمنع المسح الدائري عند تحديث ورقة `priceimg` من `DATAIMP`، استبدل كود السكريبت القديم في مصنف `priceimg` بالكود الآمن التالي الذي يقرأ القيم في الذاكرة **قبل** أي مسح، ويدمج الحقول التسويقية بواسطة `كود الصنف`:

```javascript
/**
 * دالة المزامنة الآمنة بين DATAIMP و priceimg (تمنع انزلاق الصفوف والمسح الدائري)
 */
function copyDataimpToPrice() {
  const SOURCE_SHEET_NAME = "DATAIMP";
  const TARGET_SHEET_NAME = "priceimg";

  const ss = SpreadsheetApp.getActiveSpreadsheet();
  const sourceSheet = ss.getSheetByName(SOURCE_SHEET_NAME);
  if (!sourceSheet) return;

  // 1. قراءة البيانات الحية من DATAIMP في الذاكرة أولاً قبل لمس ورقة priceimg!
  const sourceRange = sourceSheet.getDataRange();
  const sourceValues = sourceRange.getValues();
  if (sourceValues.length <= 1 || sourceValues[0].length === 0) return;

  let targetSheet = ss.getSheetByName(TARGET_SHEET_NAME);
  const enrichmentMap = {};

  // 2. بناء خريطة مرجعية (Key-Value Map) بـ «كود الصنف» لكل الصور والأوصاف والماركات الحالية في priceimg
  if (targetSheet && targetSheet.getLastRow() > 1) {
    const oldValues = targetSheet.getDataRange().getValues();
    for (let r = 1; r < oldValues.length; r++) {
      const code = String(oldValues[r][0] || "").trim();
      if (!code) continue;
      enrichmentMap[code] = {
        image: oldValues[r][7] || "",       // العمود H: رابط الصورة
        shortName: oldValues[r][8] || "",   // العمود I: اسم مختصر
        description: oldValues[r][9] || "", // العمود J: الوصف
        brand: oldValues[r][11] || "",      // العمود L: العلامة التجارية
        unit: oldValues[r][12] || "",       // العمود M: الوحدة
        condition: oldValues[r][13] || "",  // العمود N: حالة المنتج
        lastEdit: oldValues[r][14] || ""    // العمود O: آخر تعديل
      };
    }
  } else if (!targetSheet) {
    targetSheet = ss.insertSheet(TARGET_SHEET_NAME);
  }

  // 3. دمج البيانات المالية الحية مع خريطة الإثراء التسويقي عبر مطابقة كود الصنف
  const mergedValues = sourceValues.map(function(row, idx) {
    const newRow = row.slice();
    while (newRow.length < 15) newRow.push("");
    if (idx === 0) {
      newRow[7] = "رابط الصورة";
      newRow[8] = "اسم مختصر";
      newRow[9] = "الوصف";
      newRow[11] = "العلامة التجارية";
      return newRow;
    }
    const code = String(newRow[0] || "").trim();
    const saved = enrichmentMap[code];
    if (saved) {
      if (!newRow[7] || String(newRow[7]).indexOf("[link removed]") !== -1) newRow[7] = saved.image;
      if (!newRow[8]) newRow[8] = saved.shortName;
      if (!newRow[9]) newRow[9] = saved.description;
      if (!newRow[11]) newRow[11] = saved.brand;
      if (!newRow[12]) newRow[12] = saved.unit;
      if (!newRow[13]) newRow[13] = saved.condition;
      if (!newRow[14]) newRow[14] = saved.lastEdit;
    }
    return newRow;
  });

  // 4. كتابة المصفوفة المدمجة دفعة واحدة بعد اكتمال الدمج في الذاكرة
  targetSheet.clearContents();
  targetSheet.getRange(1, 1, mergedValues.length, mergedValues[0].length).setValues(mergedValues);
}
```

#### الخطوة 3: معادلة الاستيراد والترتيب الخالية من الانزلاق في `pric!0!A1`

في مصنف **[pric](https://docs.google.com/spreadsheets/d/1ev1AhcQmnhwYQuU5QV2drdGdiUW6zY6eXz4QabmFOMc/edit)** (ورقة `0` الخلية `A1`)، تُعتمد معادلة `LET + FILTER + CHOOSEROWS + SORT` التي تسحب كامل الصفوف كوحدة مترابطة واحدة (15 عموداً معاً) دون استخدام `QUERY` (التي تحذف الباركودات النصية) ودون استخدام `OFFSET` (التي ترفض مصفوفات `IMPORTRANGE`):

```excel
=LET(

  rows, CHOOSEROWS(clean, SEQUENCE(ROWS(clean) - 1, 1, 2)),
```
